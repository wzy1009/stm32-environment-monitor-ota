# STM32 环境监测与远程升级终端

基于战神 STM32F103ZET6 开发板，设计一个集温湿度监测、人体活动检测、本地报警和云端交互于一体的终端。

项目使用 DHT11 采集温湿度，SR602 检测人体活动，OLED 显示设备状态。实现本地布防与撤防、云端状态交互，并接入基于外部暂存与Bootloader安装的OTA远程更新代码。

## 当前进度

当前版本为 V0.4.0，比赛软件功能已接入，实板验收仍待完成：

- 系统时钟：8 MHz 外部晶振，PLL 倍频至 72 MHz。
- LED：LED0 每隔 500 ms 翻转一次，用于观察程序运行状态。
- DHT11：每隔约 2 秒采集温湿度，检查应答、超时和校验和。读取失败时显示错误，不把旧数据当作新数据。
- SR602：检测人体活动，上电等待 60 秒，过滤短于 100 ms 的输入脉冲。
- 按键：KEY0 切换布防/撤防，KEY1 优先撤防；默认撤防，布防后有 3 秒延时。
- 报警：布防生效后检测到人体活动，蜂鸣器间歇响、LED1 亮，报警保持到撤防。
- OLED：显示温湿度、采集状态、预热倒计时、布防状态和报警状态。屏幕出错会重试初始化。
- 云端：ESP8266 通过 MQTT 接入巴法云，上报温湿度、人体活动、布防和报警状态。
- 控制：接收 `ARM`、`DISARM`、`STATUS`，KEY1 本地撤防优先；忽略保留命令，避免重连后意外布防。
- 掉线：超时后自动重连；断网期间本地监测和报警继续运行，恢复后上报当前状态与本次开机累计报警次数。
- OTA：接收同主题JSON通知，撤防后暂停MQTT，HTTP分块下载到外部Flash，校验长度、MD5与向量，提交EEPROM标志，重启交给Boot安装。
- 失败处理：未提交且记录有效时允许恢复云连接；已有待安装请求或提交结果不明确时保护暂存镜像，不自动覆盖。
- 软件验证：本地监测、云端控制与OTA模拟回归通过；三个Keil目标的结果见[验证记录](docs/validation.md)。

接线、采集、报警以及真实联网效果仍待实板验证。公开工程不包含 Wi-Fi 密码和云端私钥，默认只运行本地功能，屏幕显示 `NET CONFIG`。填写本地配置后，按[云端接入说明](docs/cloud.md)、[OTA接入说明](docs/ota.md)和[实板演示清单](docs/demo.md)验收。未进行真实联网、烧录和整机升级，不能把软件验证当作比赛现场运行结果。

## 硬件配置

| 硬件 | 用途 |
|---|---|
| 战神 STM32F103ZET6 开发板 | 主控 |
| 128×64 OLED | 显示温湿度和设备状态 |
| DHT11 | 温湿度采集 |
| SR602 | 人体活动检测 |
| 板载有源蜂鸣器 | 本地报警 |
| ESP8266 | Wi-Fi 联网，与巴法云通信 |
| W25Q128 / 兼容SPI Flash | 暂存待安装固件 |
| AT24C02 | 保存升级元数据与安装标志 |

SR602 用于检测人体活动，不能可靠判断静止人员是否仍在。接口与引脚信息见 [硬件说明](docs/hardware.md)。

本版接线：DHT11 DATA → PG11，SR602 OUT → PG10；KEY0 为 PE4、KEY1 为 PE3，板载蜂鸣器为 PB8。传感器与开发板共地，模块引脚顺序以实际标识为准。

## 编译与运行

1. 运行 `./tools/build.ps1 -KeilRoot E:\keil5`，或在Keil分别构建 `ENV_OTA`、`ENV_BASE` 和 `OTA_BOOT`。
2. 正式OTA配置：Boot位于 `0x08000000`，`ENV_OTA` APP位于 `0x08008000`；首次烧录两个HEX，按[OTA说明](docs/ota.md)确认初始化和分区。
3. 单独验证本地监测可用 `ENV_BASE`，但它起点为零，会覆盖Boot，不能当作OTA固件。
4. 预热结束后测试布防、报警、撤防和云端控制；设备撤防后才启动升级。
5. 修改 `FIRMWARE_VERSION` 构建新版本，用 `tools/prepare_ota.py` 生成包含实际大小、MD5的通知。

烧录前备份板上原固件并检查擦除范围。远程升级只下发 `ENV_OTA.bin`，不下发HEX、Boot或 `ENV_BASE`。当前为明文MQTT/HTTP与MD5一致性校验，不含签名认证、A/B回滚或可信防降级。

编译结果与待验证内容见 [验证记录](docs/validation.md)。
