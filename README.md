# STM32 环境监测与远程升级终端

之前做过一套 STM32 OTA 项目，这次想给它加上实际的监测和报警功能。手头正好有 DHT11 和 SR602，就准备用它们做一个能看温湿度、检测人体活动的小终端。

本地用 OLED 显示数据，布防后检测到人体活动就报警；联网后，可以在云平台查看状态、控制布防和撤防。后面再接入原来的 OTA，让设备不用接电脑也能更新程序。

## 现在做到哪了

目前先把基础工程整理出来了，用的是战神 STM32F103ZET6 开发板，从原来的 OTA 工程复制后单独开发。

这一版包含系统时钟、LED 和 OLED 驱动：外部 8 MHz 晶振倍频到 72 MHz，LED0 每隔 500 ms 翻转一次，OLED 显示项目名称和启动信息。屏幕初始化或显示失败时，LED1 会常亮。

工程已经在 Keil 下编译通过，0 错误、0 警告，还没做这一版的实板烧录验证。DHT11、SR602、报警和联网功能接下来逐步加，原来的 OTA 也还没有合进这个仓库。

## 用到的硬件

- 战神 STM32F103ZET6 开发板
- 128×64 OLED，沿用原项目的接线
- DHT11：采集温湿度
- SR602：检测人体活动
- 板载有源蜂鸣器：本地报警
- ESP8266：连接 Wi-Fi 和巴法云

其中 DHT11、SR602、蜂鸣器和 ESP8266 是后续要接入的部分。SR602 检测的是人体活动，不能用它可靠判断一个静止的人是否还在。

已确认的接线和待核对的引脚放在 [硬件说明](docs/hardware.md) 里。

## 怎么编译

当前使用的环境：

| 工具 | 版本 |
|---|---|
| IDE | Keil µVision 5 |
| 编译器 | ARM Compiler 5.06 update 6，build 750 |
| 设备包 | Keil STM32F1xx_DFP 2.3.0 |

HAL 和 CMSIS 已经放在工程里，不需要另外复制。

打开 `firmware/MDK-ARM/ENV_BASE.uvprojx`，选择 `ENV_BASE`，执行 Rebuild。生成的 HEX 在 `firmware/MDK-ARM/Objects/`，编译记录见 [验证记录](docs/validation.md)。

**烧录前注意：这一版是独立运行的基础程序，起始地址是 `0x08000000`。直接烧录会覆盖原来的 BootLoader，要先备份；它不能作为原 OTA 工程的升级包使用。**

## 接下来准备做

先接 DHT11 和 SR602，把温湿度、人体活动状态显示到屏幕上，再加按键布防和蜂鸣器报警。

本地功能跑通后接巴法云，做数据上报、远程布防和撤防。最后把原来的 OTA 接进来，演示从云端发布固件到设备更新的完整过程。
