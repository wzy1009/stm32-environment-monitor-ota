# 实板演示清单

下面是待执行清单，不代表测试结果。记录实际日期、板卡、接线、AT固件版本、构建Target、APP版本和对应BIN文件；保留串口日志与屏幕照片，不填估算成功率、耗时或距离。

## 准备

- 核实 [硬件接线](hardware.md)、供电及共地；确认W25Q128、AT24C02和ESP8266实际连接。
- 按 [OTA说明](ota.md) 构建Boot和 `ENV_OTA`，备份板上原固件，分别首次烧录；记录Boot初始化入口关闭和APP启动日志。
- 本地配置Wi-Fi/云端凭据；确认 `NET ONLINE` 和 `envState` 最新上报，检查上报版本与本次构建一致。
- 准备版本不同的新 `ENV_OTA.bin`，记录实际字节数、MD5、下载URL和构建来源；确认HTTP直接返回200、Content-Length正确。

## 本地与云控制

- 记录DHT11读数及错误状态；不要把示例温湿度当测量值。
- 等待PIR就绪，执行ARM、活动触发、DISARM及KEY1本地撤防；记录屏幕、蜂鸣器与云状态是否一致。
- 断网再恢复，观察本地功能和重连后上报；记录实际恢复时间及异常。

## OTA 正常路径

- 先布防，发送新版本OTA通知，观察请求是否等待；撤防后确认在DHT空闲窗口启动。
- 记录 `NET OTA`、暂存擦除、下载、校验、提交和复位日志。OTA期间MQTT由下载器独占，普通云命令/状态上报不应被当作实时可用。
- 复位后记录Boot暂存校验、内部安装、pending清除及APP跳转，再检查屏幕和云上报版本。
- 重启一次，确认不会重复安装；重新检查温湿度、布撤防和报警功能。

## 拒绝与故障路径

- 下发同版本、缺字段、错误长度或错误MD5通知，分别记录拒绝/失败阶段及内部APP是否保持可启动。
- 在提交前中断HTTP连接或Wi-Fi，观察是否判定可恢复、恢复MQTT；重新下发正确通知并记录结果。
- 提交/安装断电试验应单独安排，保留串口和供电操作记录及有线恢复工具；记录复电后pending、重试安装或停留错误状态，不能预先认定可恢复。
- 检查元数据异常时是否停止危险写入；不要为演示直接清EEPROM、覆盖Boot或把初始化入口重新打开冒充恢复。

每项结果填写“实际现象、日志/照片、是否符合预期、未解决问题”。尚未执行的项目保持“待实板验证”。当前不宣称HTTPS、签名认证、A/B回滚或首次启动健康确认。
