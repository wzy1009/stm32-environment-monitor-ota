# 验证记录

## V0.4.4 MQTT 登录确认兼容修正（2026-10-26）

- 使用生产 `Mqtt_Connect` 生成报文，从电脑对 `bemfa.com:9501`、`mqtt.bemfa.com:9501` 进行真实握手。两者对原请求返回 `20 02 01 00`，返回码表示成功，但旧解析器因 Session Present 为 1 错误拒绝。
- 改为与原工程相同的持久会话请求，并允许符合格式的 Session Present 0/1。再次用生产编解码模块实连云端，收到 `20 02 00 00` 且解析为连接成功；仅 CONNECT/DISCONNECT，没有发送控制或发布消息。
- 只读确认截图中的比赛主题已创建，本地固件切换到 `envCmd`/`envState`，按主题过滤旧工程频道消息。
- 建立连接前显式设置主动接收及 IPD 格式；模拟测试检查设置顺序、已有会话握手和保留位/未授权返回码拒绝。Keil 应用与 Boot 零错误零警告，本机回归通过。
- 上述实连验证位于电脑侧，实际 MCU 的 UART/Wi-Fi/MQTT 全链路仍需烧录后确认。

## V0.4.3 ESP 接收错误修正（2026-10-26）

- 修复错误计数检查在 ESP 复位阶段触发重试、导致不断复位的逻辑；只在 RETRY/BOOT 丢弃已知无应用数据的启动窗口，AT 握手前建立新基线。
- 新增回归先在 V0.4.2 重现无法上线，再验证修正后连续注入启动帧错误仍能完成 AT/MQTT 握手。正常通信时的帧错、噪声、硬件溢出、重启接收失败、软件队列满仍中止连接。
- 屏幕进一步区分接收错误类型。Keil 应用与 Boot 编译零错误零警告，本机模拟测试通过。尚未采集实际模块启动波形，不能将模拟结果作为本板故障原因的实测确认。

## V0.4.0 收尾（2026-10-26）

- 一个 Keil 工程入口，只有一个应用目标 `ENV_APP`，另一个目标 `ENV_BOOT` 负责启动与安装。HAL、外设驱动和 OTA 格式均为共用源码。
- ARM Compiler 5.06 update 6 build 750：公开空配置与本地私有配置均编译通过，应用与 Boot 为 0 Error(s)、0 Warning(s)。
- 公开配置构建：APP Code 32236 B、RO-data 2168 B、RW-data 268 B、ZI-data 13764 B；Boot Code 19136 B、RO-data 852 B、RW-data 56 B、ZI-data 7104 B。
- 生产代码的本地监测、云端、下载、安装和打包检查通过，覆盖内容见 [tests](../tests/README.md)。安装写入/擦除/读回/记录故障后，保留暂存和 pending 再次安装的模拟检查通过；无效暂存/记录/向量时不执行应用擦除。
- 联合 HEX 与实际 BIN 检查通过：分区、启动向量、HEX 校验和、Boot 一次性标记的文件内容与地址。链接映射中的 `BOOT_SETUP` 是固定 `0x08007800` 的只读区，加载地址与执行地址一致。
- 启动文件栈为 4096 B；链接器列出的静态最大栈用量 APP 1200 B、Boot 1128 B，含未知调用链提示，不能据此替代实际栈水位检查。
- 本地生成初始固件和不同版本的演示升级固件，保留真实大小与 MD5。构建产物、联网私钥和密码不提交 GitHub。

仍待实板：首次烧录与初始化、真实传感器/屏幕/蜂鸣器、ESP8266 AT 兼容性、巴法云收发、实际下载与安装、安装断电、长时间运行。没有这些步骤的实测结果、照片或视频。设备升级成功需要观察新应用运行并重新上报版本；当前没有实现首次启动健康确认、A/B 或旧固件回滚。
