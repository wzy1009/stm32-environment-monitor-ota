# 本地监测与报警

当前固件 V0.4.4。本地监测代码已编译并通过本机测试，以下步骤待实板执行；云端配置另见 [云端接入](cloud.md)。

## 接线与烧录

1. DHT11：VCC→3.3 V、DATA→PG11（P13-2）、GND→GND。四脚器件 NC 不接，三脚模块按标识接线。
2. SR602：OUT→PG10（P10-22），GND→开发板 GND；确认模块支持 3.3 V 供电后再连接 VCC。
3. OLED：SCL→PD9、SDA→PE15，电源 3.3 V，并共地。
4. KEY0、KEY1、蜂鸣器和 LED 使用板载器件。
5. 打开 `firmware/MDK-ARM/ENV_BASE.uvprojx`，选择 `ENV_APP` 并 Rebuild，生成 `Objects/APP/ENV_APP.hex`，首次烧录须配套 `ENV_BOOT`。

当前 APP 从 `0x08008000` 运行，Boot 从 `0x08000000` 运行；首次烧录前备份需要保留的程序与数据。HEX 用于初始烧录，OTA 使用原始 APP BIN。

## 显示与操作

| 屏幕 | 含义 |
|---|---|
| `TEMP 24.4 C` / `HUM 53.0 RH` | 温度与相对湿度；这里是示例值，不是实测 |
| `DHT WAIT` | 等待首次读取 |
| `DHT TIMEOUT` | 无应答或时序超时 |
| `DHT CHECKSUM` / `DHT DATA ERROR` | 校验或字段错误，温湿度改为占位符 |
| `PIR MOTION` / `PIR CLEAR` | 已过滤的活动输入状态 |
| `MODE DISARMED` / `MODE ARMING` / `MODE ARMED` | 撤防 / 3 秒布防等待 / 已布防 |
| `ALARM ON` | 报警保持，直到撤防 |
| `NET CONFIG` / `NET ONLINE` | 缺少或无效配置 / MQTT 订阅成功；其余阶段提示见云端接入说明 |

KEY0 单次按下切换布防/撤防，长按不重复；KEY1 优先撤防并清除报警，双键同按保持撤防。重启后默认撤防，不保存布防状态。

布防生效后，SR602 高电平持续至少 100 ms 触发报警。如果延时结束时输入已为高，也会报警。人离开不会自动清除报警，需要撤防。

报警时蜂鸣器约 200 ms 响、200 ms 停，LED1 常亮。LED1 同时用于 OLED 故障提示，不能单凭它判断人体活动。

## 实板检查

1. 上电保持撤防：LED0 闪烁，屏幕显示监测状态，蜂鸣器不响。
2. 等约 2 秒查看温湿度；若出错，检查数据线、供电、上拉和模块型号。
3. 布防延时结束后在撤防状态走动：应显示活动，但不报警。
4. KEY0 布防，离开感应区，等延时结束再进入：应报警。
5. 离开后报警继续；按 KEY1 应停止并恢复撤防。
6. 断开 DHT11 DATA 应报超时，按键与人体检测仍可工作；接回后应恢复采集。

当前不额外屏蔽 SR602 上电输入，默认撤防；按键布防后仍等待 3 秒。模块上电瞬态、触发范围和输出保持时间需实测。

## 实现与边界

DHT11 约每 2 秒读取一次。启动低电平由状态机保持约 20 ms，然后用 DWT 周期计数轮询应答和数据，每个等待均有超时；失败后清除有效标记，下个周期重试。接收期间不关闭全局中断，仍会短时占用主循环。后续加入高频中断或联网业务后需重测时序，必要时改用定时器捕获。

温湿度按整数保存十分位，显示小数不代表测量精度。小数、负温符号位、校验和与启动时序参考 [奥松 DHT11 产品手册](https://aosong.com/userfiles/files/media/DHT11%E6%95%B0%E5%AD%97%E6%B8%A9%E6%B9%BF%E5%BA%A6%E4%BC%A0%E6%84%9F%E5%99%A8%E6%A8%A1%E5%9D%97.pdf)。

OLED 每约 250 ms 准备一帧，分步发送，发送完成前不改写帧缓冲。失败后约 2 秒重试初始化。有源蜂鸣器使用 GPIO 开关，不需要 PWM。
